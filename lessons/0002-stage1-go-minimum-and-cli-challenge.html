CATEGORY 01

语言基础

值、容器、接口、错误

Go 先用显式的值语义建立一个稳定心智：变量有零值，容器有共享行为，接口看方法，错误靠返回值。

Zero value

声明后已经是可用起点

数字是 0，字符串是 ""，布尔是 false，指针、slice、map、channel、函数和接口是 nil。

nil slice 可 append；nil map 可读但写入会 panic，写之前先 make。

Slice

指针 + 长度 + 容量

append 在容量够时可能复用底层数组，容量不够时才分配新数组。共享底层数组会让“另一个 slice 的修改”出现在当前值里。

需要独立副本时，显式复制：append([]int(nil), a...)。

Map

查找用 comma-ok

v, ok := m[k] 能区分“零值”和“键不存在”。复制 map 变量会共享同一份底层数据，不是深拷贝。

map 的遍历顺序不保证；元素增多后运行时会自动扩容并重新分布键，所以不要依赖内部位置。

Struct & method

方法接收者决定修改是否可见

值接收者拿到副本；需要修改或避免大对象复制时用指针接收者。一个类型和它的方法必须定义在同一包中。

var counts map[string]int // nil
counts = make(map[string]int)

type User struct {
    Name string
}

func (u *User) Rename(name string) {
    u.Name = name
}

func (u User) Describe() string {
    return u.Name
}

type Describer interface {
    Describe() string
}

var _ Describer = User{} // 编译期检查：User 是否满足 Describer

接口是隐式实现

类型不需要写 implements。只要方法集合满足接口，它就自动实现接口。优先定义“使用方真正需要的小接口”，例如 io.Writer，不要为了抽象先造大接口。

错误要带上下文，也要保留因果链

func loadConfig(path string) ([]byte, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return nil, fmt.Errorf("load config %q: %w", path, err)
    }
    return data, nil
}

if errors.Is(err, fs.ErrNotExist) {
    // 调用方仍能判断底层原因
}

fmt.Errorf(..., %w, err) 包装错误；errors.Is 判断因果链中的某个错误；errors.As 取出链中的特定错误类型。

defer 收尾，panic 只处理意外

func closeFile(f *os.File) {
    defer f.Close() // 后注册先执行，常用于释放资源
}

func guard() {
    defer func() {
        if r := recover(); r != nil {
            log.Printf("recovered: %v", r)
        }
    }()
}

普通失败返回 error，不要拿 panic 当控制流。recover 只在 defer 中有效，适合守住进程边界，不适合掩盖错误。

到此为止：能解释例子并写出自己的 struct、接口、包装错误和 defer 收尾即可。不进入反射和 unsafe。

主来源：A Tour of Go 补充：Go 官方错误包装
合上笔记：为什么 nil slice 能 append，nil map 却不能直接写？

append 能为 nil slice 分配新底层数组；map 写入需要已初始化的哈希表，所以无索引赋值前要 make(map[...]...)。

CATEGORY 02

并发

启动、通信、取消

最低目标不是背调度器，而是能安全启动工作、等待完成、传值和取消。并发只是工具，题目不需要时就不要强塞。

Goroutine

启动容易，退出要负责

go fn() 异步启动。main 返回时进程结束，不会等待所有 goroutine；每个长期运行的任务都需要停止条件。

Channel

无缓冲同步，有缓冲排队

无缓冲发送要等接收方；有缓冲只在缓冲区满时阻塞。只由发送方关闭 channel，接收方用 v, ok := <-ch 判断是否关闭。

Select

等待多个通信点

多个 case 同时就绪时随机选一个。default 让 select 立即返回，可用于非阻塞检查；nil channel 的收发会一直阻塞。

Sync

共享状态先加锁，再等待

Mutex 保护共享写入；WaitGroup.Add 必须在启动 goroutine 前完成；Once.Do 保证初始化只执行一次。

var (
    mu   sync.Mutex
    once sync.Once
)

func add(x *int, delta int) {
    mu.Lock()
    defer mu.Unlock()
    *x += delta
}

var wg sync.WaitGroup
for _, item := range items {
    wg.Add(1)
    go func(value int) {
        defer wg.Done()
        add(&total, value)
    }(item)
}
wg.Wait()

defer wg.Done() 避免中途 return 漏掉计数。若多个 goroutine 的返回值要汇总，优先用带缓冲 channel 或加锁的局部结果，不要在多个 goroutine 里无保护地写同一个 map。

context 负责传递取消信号

ctx, cancel := context.WithTimeout(parentCtx, 2*time.Second)
defer cancel()

select {
case result := <-work:
    return result, nil
case <-ctx.Done():
    return nil, ctx.Err()
}

把 ctx 放在函数第一个参数并向下传递。取消是协作式信号，不会强行杀死 goroutine；受控任务需要在等待或循环处检查 ctx.Done()。

到此为止：能解释无缓冲/有缓冲 channel、用 select 收口、正确放置 WaitGroup.Add、向下传 context 即可。不进入 GMP 细节。

主来源：A Tour of Go · Concurrency 补充：context 标准库
合上笔记：为什么 WaitGroup.Add 不能放在 goroutine 内部？

如果 Wait 已先执行，内部 Add 可能还没发生，Wait 就会提前返回。先 Add，再启动 goroutine，才能稳定等待全部任务登记完成。

CATEGORY 03

工程化

能建、能测、能检查

这一段把“会写语法”变成“能交付一个小项目”。最低闭环是 module、包、格式化、测试、竞态检查和一次 benchmark。

从 module 和包开始

mkdir filemix
cd filemix
go mod init example.com/filemix

gofmt -w $(find . -name '*.go' -type f)
go vet ./...
golangci-lint run ./...

go.mod 记录模块路径和依赖。包名短、全小写、表达职责；一个目录内只放一个包。先保持 package main 与一个辅助包就够，不要为了“架构感”拆很多层。

测试先写表，再写多组输入

func TestCountByExt(t *testing.T) {
    tests := []struct {
        name string
        files []string
        want map[string]int
    }{
        {name: "mixed", files: []string{"a.go", "b.GO"}, want: map[string]int{".go": 2}},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := countByExt(tt.files)
            if !reflect.DeepEqual(got, tt.want) {
                t.Fatalf("got %v, want %v", got, tt.want)
            }
        })
    }
}

表格驱动测试把输入、期望和用例名放在同一张表里。`reflect.DeepEqual` 在测试里比较 map 可以接受；业务代码仍优先写清楚比较逻辑。

竞态检查与 benchmark

go test -race ./...
go test -bench . -benchmem ./...

-race 会在运行时探测实际走到的数据竞争，不是静态证明。benchmark 用固定输入循环 b.N 次，报告每次操作耗时和内存分配：

func BenchmarkCountByExt(b *testing.B) {
    files := []string{"a.go", "b.md", "c.go"}
    b.ResetTimer()
    for i := 0; i < b.N; i++ {
        _ = countByExt(files)
    }
}

到此为止：能初始化 module、用 gofmt/vet/lint 检查、写表格驱动测试、跑 race 和 benchmark 即可。不研究编译优化或链接器。

主来源：Go Modules Reference 补充：Race Detector
合上笔记：验收一个小 Go 项目，最少跑哪四条命令？

格式化检查或写入、go vet ./...、go test -race ./...、go build ./...。需要性能判断时再加 go test -bench . -benchmem ./...。

CATEGORY 04

常用标准库

会查、会用、会收资源

这里只建立“遇到任务知道去哪个包”的最低地图。不会的 API 查 pkg.go.dev，不要背函数表。

任务必须会的最小 API
net/http NewServeMux、HandleFunc、ListenAndServe；handler 写状态码和 body。
encoding/json Marshal / Unmarshal，或流式 Encoder / Decoder；结构体 tag 控制字段名。
time time.Now、time.Since、time.Duration、time.NewTimer / time.NewTicker。
os os.Args、ReadFile / WriteFile、os.Stderr、os.Exit。
io Reader / Writer、io.Copy；泛用接口让函数不绑定具体文件。
database/sql Open、PingContext、QueryContext、QueryRowContext、ExecContext、Scan、Close。

HTTP 与 JSON 的最低组合

mux := http.NewServeMux()
mux.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "application/json")
    _ = json.NewEncoder(w).Encode(map[string]bool{"ok": true})
})

log.Fatal(http.ListenAndServe(":8080", mux))

没有显式写状态码时默认是 200。Encoder.Encode 直接写响应流，适合 handler；Marshal 适合先拿到字节。

文件、IO 与数据库的共同习惯

data, err := os.ReadFile(path)
if err != nil {
    return fmt.Errorf("read %s: %w", path, err)
}

if _, err := io.Copy(dst, src); err != nil {
    return fmt.Errorf("copy: %w", err)
}

db, err := sql.Open("driver-name", dsn)
if err != nil {
    return err
}
defer db.Close()

if err := db.PingContext(ctx); err != nil {
    return fmt.Errorf("ping database: %w", err)
}

sql.Open 不一定立即建立连接，所以要 PingContext。查询返回的 *sql.Rows 必须 Close，并检查 rows.Err()。数据库驱动在进入实际数据库阶段时再选。

到此为止：能查文档并组合这些 API，处理返回错误和资源释放即可。不背冷门包，也不在本阶段展开 HTTP 原理。

主来源：net/http 文档 题目补充：path/filepath 文档
合上笔记：为什么 sql.Open 成功后还要 PingContext？

sql.Open 主要准备连接池配置，通常不会证明数据库可达；PingContext 才实际检查连接是否可用，并受 context 取消控制。

阶段过关题 / 01

写一个 filemix

题目对应路线阶段 1 的唯一 Go 过关标准：用 Go 写一个命令行小工具，统计目录下文件类型分布。这里的“类型”明确指文件扩展名。

交付物

一个可构建的 Go 项目：main.go、必要的辅助文件、至少一个 _test.go。

环境

在 Linux 或 WSL 的 shell 中构建并运行。只能使用 Go 标准库。

完成定义

源码、测试、验收命令都通过，并能解释关键选择和错误处理。

命令行为

filemix <dir>
  • 参数必须恰好是一个目录；缺失、多余或路径不是目录时，错误写入 stderr，进程以非零状态退出。
  • 递归遍历该目录，统计所有普通文件；包含隐藏文件和隐藏目录；遇到读取错误就整体失败，不输出半份结果。
  • 扩展名统一转小写后合并，例如 .PNG 与 .png 算同一类；没有扩展名的文件归入 (none)。
  • 先按数量从多到少排序；数量相同则按类型字符串升序排序。
  • 最后输出 TOTAL 行，数值是普通文件总数。目录和符号链接都不计入。

输出协议

先输出表头 TYPE<TAB>COUNT，每个类型一行，字段之间是一个制表符。空格只用于下面的视觉对齐，判题时忽略行尾空白。

TYPE    COUNT
(none)  1
.env    1
.gz     1
.json   1
.png    1
.go     3
TOTAL   8

运行参数错误时不要打印空表；把具体错误写到 stderr。示例：filemix: open demo: permission denied。

验收夹具

在项目根目录执行下面这段 Linux shell，创建固定输入：

mkdir -p demo/sub
printf 'package a\n' > demo/a.go
printf 'package c\n' > demo/b.go
printf 'package d\n' > demo/sub/c.go
printf '# demo\n' > demo/README
printf '{}\n' > demo/data.json
printf 'x\n' > demo/archive.tar.gz
printf 'PORT=8080\n' > demo/.env
printf 'png\n' > demo/sub/logo.PNG

然后构建并检查输出：

GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o filemix .
./filemix ./demo
./filemix ./missing ; test $? -ne 0
