CATEGORY 01

命令行

定位与排查

你只需要在 Linux 终端里找到文件、改内容、筛选输出、设置本次会话的环境变量，以及查出端口被哪个进程占了。

任务最低命令
看当前位置 / 进入目录 / 列文件pwd、cd 路径、ls -al
新建 / 读取 / 改写 / 删除文件touch notes.txt、cat notes.txt、printf 'hello\n' > notes.txt、rm notes.txt
复制 / 移动cp a.txt b.txt、mv a.txt backup/a.txt
管道筛选文本cat app.log | grep "ERROR"
读取 / 设置环境变量echo "$JAVA_HOME"、export GOPATH="$HOME/go"
查进程 / 查端口ps aux、ss -lntp

端口占用就用一条链收口：先查占用者，再确认进程身份。

sudo ss -lntp | grep ':8080'

ps -fp <PID>

到此为止：不学 Linux 权限模型、shell 脚本或 systemd。知道怎么执行上面的命令就够了。

来源：GNU Coreutils 手册 来源：Linux man-pages · ss
CATEGORY 02

Git

提交、同步、收冲突

最低流程是：初始化或克隆，提交本地改动，推到远程；有分支就合并；冲突时改到最终版本，再提交。

把本地项目送上去

git clone <远程仓库地址>

git init
git add .
git commit -m "chore: initialize project"
git branch -M main
git remote add origin <远程仓库地址>
git push -u origin main

日常提交与分支

git status
git diff
git switch -c feature/stage0
git add .
git commit -m "feat: add stage0 practice"
git switch main
git merge feature/stage0

冲突的标准收口

git pull origin main
# 编辑冲突文件，保留最终内容，删除 <<<<<<< ======= >>>>>>>
git add .
git commit
git push

.gitignore 至少挡住不该进仓库的东西：

.env
node_modules/
*.log

发 PR 只需要两类动作：功能分支推上远程，然后在远程仓库页面比较该分支和主分支。

到此为止：不学 Git 对象模型、rebase、cherry-pick。会用 merge 和冲突闭环即可。

来源：Pro Git · 分支与合并 来源：GitHub Docs · 创建 PR
CATEGORY 03

编辑器

跳转、断点、格式化

选择 VS Code 这一条路径即可。装好 Go 扩展后，记住三个动作：

动作怎么做到
跳转定义把光标放在符号上，按 F12；或按住 Ctrl 点击。
断点调试在行号左侧点红点，按 F5，选择 Go 调试配置；断住后用 F10 单步、看变量。

验收方法：写一个两数相加的 Go 小程序，在相加那行打断点，停住后读出两个参数的值；保存前格式化一次。

CATEGORY 04

数据格式

读结构、写配置

JSON 只需要会读写对象、数组、字符串、数字、布尔值和 null，并看懂嵌套。

{
  "user": {
    "id": 7,
    "roles": ["admin", "dev"],
    "active": true
  }
}

在 Linux 终端里用 cat 读、用重定向写，确认你知道哪里是对象、哪里是数组：

cat user.json
printf '%s\n' '{"name":"Ada","tags":["go","sql"]}' > user.json

YAML 只看缩进、键值和小列表。冒号后要有空格，同层缩进必须一致，不用 Tab。

    - localhost
    - 127.0.0.1

Markdown 至少要会标题、列表、代码块和链接：

# 标题

- 列表项
- 另一个列表项

`行内代码`

```bash
echo "code block"
```

[链接文字](https://example.com)

到此为止：不学 JSON Schema、YAML 锚点与高级 Markdown 扩展。

CATEGORY 05

接口调试

方法、Header、Body

Postman、Apifox 和 curl 本质上都在填同一张表：请求方法、URL、Header、Body。带登录态时，再填 Authorization。

curl -X POST "http://localhost:8080/api/users" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"name":"Ada"}'
部分这行在说什么
-X POST创建资源，通常把数据放在请求体里。
URL请求发往哪个服务、哪个资源。
Content-Type告诉服务端 body 是 JSON。
Authorization带上身份凭证；Token 不要提交进 Git。
-d发送请求体。

在 Linux 终端中直接使用 curl，反斜杠 \ 表示下一行仍是同一条命令。

到此为止：不学 OAuth、签名算法和 API 设计。会组装并发送一条带 Header、Body、Token 的请求就够了。

来源：curl 官方手册
CATEGORY 06

抓包与调试

读一条请求

打开浏览器 DevTools 的 Network 面板，刷新页面，点中任意一条请求。你至少要能说出下面五项：

字段你必须读出的信息
Name / URL请求了哪个接口。
MethodGET 查询，POST 提交，PUT/PATCH 更新，DELETE 删除。
Status2xx 成功，4xx 请求或身份问题，5xx 服务端问题。
Time这条请求总共花了多久。
Headers / Payload / Response带了什么、发了什么、服务端回了什么。

例如看到 POST /api/login · 401 · 142 ms，你能确定的是：请求已经发到服务端，服务端拒绝了登录，整个往返用时约 142 毫秒。仅凭这一行，不能断言是密码错、数据库坏，还是前端写错。

到此为止：不学 TCP/TLS 握手、HTTP 缓存机制或性能优化。会读请求和响应即可。

来源：Chrome DevTools · Network
CATEGORY 07

容器

起库、连库、建表

只做一件事：把 MySQL 8.4 放进容器，让宿主机通过 3307 访问容器的 3306。

docker run -d \
  --name mysql-stage0 \
  -p 3307:3306 \
  -e MYSQL_ROOT_PASSWORD=stage0 \
  -v mysql_stage0:/var/lib/mysql \
  mysql:8.4

-p 3307:3306 的顺序是“宿主端口:容器端口”。这里宿主 3306 可能已经被占用，所以换成 3307，容器里的 MySQL 仍然是 3306。

确认容器状态，并进入容器里的 MySQL 客户端：

docker ps
docker exec -it mysql-stage0 mysql -uroot -pstage0

连接后执行最低 SQL：

CREATE DATABASE stage0;
USE stage0;
CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL
);
SHOW TABLES;

如果启动失败，先看 docker logs mysql-stage0，不要先拆镜像或研究 Docker 原理。

到此为止：不学 Dockerfile、Compose、镜像分层和网络模式。能 run、连上、建库建表即可。

来源：Docker Hub · MySQL 官方镜像
